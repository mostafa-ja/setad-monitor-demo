معماری مهندسی سامانه پایش و حل خودکار کپچا

Two-Phase Scraping Pipeline & Deep OCR Architecture
⚡ فاز ۱: ورود سریع داده‌ها (Fast Bulk Ingestion)

واکشی آنی و بدون معطلی تمامی فراخوان‌های جدید بدون نیاز به کپچا تا عمق زمانی تعیین‌شده. ثبت بلادرنگ در SQLite و ارسال هشدار فوری زیر ۱ ثانیه به کانال تلگرام به محض تطبیق عنوان با کلمات کلیدی.

نرخ پذیرش: ~500 فراخوان در 4 ثانیه کپچا: خیر
🤖 فاز ۲: حل کپچا با هوش مصنوعی (Deep OCR)

رتبه‌بندی مناقصات با الگوریتم اولویت تجاری (کلیدواژه‌ها > مهلت‌های کمتر از ۳ روز > مناقصات امروز). ارسال تصویر کپچا به مدل CNN یادگیری ماشین (ddddocr) با دقت ۹۹.۲٪ و استخراج مبالغ تضمین، شبا و اسناد فنی.

دقت مدل: 99.2% زمان پردازش: 0.78s
// SYSTEM WORKFLOW PIPELINE
[CRON / APScheduler / Manual] ────────► [FastAPI Web Engine] │ ┌────────────────────────────────────────────┴───────────────────────────────────────────┐ ▼ ▼ [Phase 1: Fast Bulk Ingestion] [Phase 2: Priority OCR Worker] • Lookback API query (3-7 days) • Candidates Queue: Priority Algorithm • Zero Captcha Required • Download Captcha Image (JPEG) • Insert/Update seen.db (WAL Mode) • Predict via ddddocr CNN Model (99.2%) • Trigger Instant Stage-1 Telegram Alert • Extract: Guarantee, Estimate, Documents • Trigger Stage-2 Financial Telegram Alert • Live Sync to TenderSheet.xlsx

چرا این معماری حائز اهمیت مهندسی است؟

  • مقاومت در برابر اختلالات شبکه: فرآیند دو فازی مانع از این می‌شود که سختی یا تاخیر کپچا باعث عقب افتادن چرخه آگاهی تیم از مناقصات جدید شود.
  • بهینه‌سازی منابع و سهمیه کپچا: به جای حل بیهوده کپچا برای هزاران مناقصه غیرمرتبط، مدل هوش مصنوعی تنها مناقصاتی را پردازش می‌کند که فوریت زمانی یا تطابق کلیدواژه دارند.
  • پایگاه داده سبک و فوق‌سریع: بهره‌گیری از SQLite در حالت WAL Mode با کش در حافظه (Memory Cache) جهت پاسخگویی به درخواست‌های وب زیر ۵ میلی‌ثانیه.
  • حفظ مالکیت معنوی: هسته اسکرپر، کلیدواژه‌های تجاری و اسکریپت‌های اتوماسیون محرمانه مانده و تنها رابط کاربری تعاملی در گیت‌هاب پیجز میزبانی می‌شود.
